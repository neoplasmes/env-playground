# Работа с агентами

Правила репозитория находятся в `AGENTS.md`, роли — в `.codex/agents/`, навыки —
в `.agents/skills/`. Настройки действуют для этого проекта; GitHub MCP не добавляется.

Общие инструменты находятся в `node/`: commitlint, Git hook, конфигурация и
сценарии Playwright, активация окружения. Их зависимости закреплены в основном
`node/package.json` и `node/pnpm-lock.yaml`. В `node/tools/agent-workflow/` остаются
MCP и Playwright CLI для исследования страниц агентом; это отдельный пакет.

## Установка на новом компьютере

Сначала установи инструменты проекта по `README.md`. Для локального набора этого
компьютера выполни `source node/activate.sh`. Эта обёртка
активирует инструменты через существующий bootstrap и, если системного `cc` нет,
подключает уже установленный локальный C-компилятор из `.cache/native`.

```bash
moon run playground:node-install
moon run playground:agents-install
moon run playground:node-hooks
moon run playground:browser-install
moon run playground:terraform-mcp-install
```

Команды `node-install` и `agents-install` ставят общие Node-инструменты и отдельные
инструменты агентов. `node-hooks` включает проверку сообщений коммитов в этом
checkout, `browser-install` загружает Chromium в `.cache/playwright`.
Последняя ставит Terraform MCP из официального архива с проверкой закреплённой
SHA-256; для распаковки нужен `unzip`. Docker и Go для этого не требуются.
Если Chromium сообщает о недостающих системных библиотеках, установи их через
пакетный менеджер ОС; установка браузера сама не меняет системные пакеты.

Открой следующую сессию Codex в этом репозитории, чтобы загрузить новые настройки,
агентов и skills. Проект должен быть доверенным: Codex не загружает проектную
конфигурацию из недоверенных каталогов. Проверить список MCP: `codex mcp list`.

## Как распределяется работа

| Агент | Когда нужен | Результат |
| --- | --- | --- |
| `architecture-reviewer` | Меняются границы слоёв, контракты или владение состоянием | Замечания с конкретными зависимостями и последствиями |
| `code-reviewer` | Завершено содержательное изменение | Воспроизводимые ошибки и пробелы проверки |
| `platform-engineer` | Terraform, Helm, k3s, Docker, Woodpecker | Проверенное изменение или обоснованная диагностика |
| `browser-qa` | Меняется пользовательский сценарий | Шаги, наблюдения, ошибки, артефакты |

Основной агент отвечает за реализацию, объединение результатов и логические
коммиты. Ревьюеры читают код; браузерный агент может создавать тесты и артефакты.
Параллельные изменения выполняются в разных worktree или непересекающихся файлах.
Worktree — отдельная рабочая папка того же Git-репозитория со своей веткой.

Примеры запросов:

- «Добавь преобразование изображения. Используй `$image-processing-change`,
  согласуй контракты и проверь результат через `$verify-change`».
- «Проведи независимое ревью изменений агентом `code-reviewer`».
- «Проверь загрузку и скачивание через `browser-qa`, сохрани доказательства».
- «Разберись, почему preview не появился, через `$preview-diagnostics`».

## Навыки и документация

Собственные skills: `verify-change`, `image-processing-change`, `preview-diagnostics`.
Внешние: Vercel React Best Practices, HashiCorp Terraform Style Guide и Microsoft
Playwright CLI. Их точные ревизии, лицензии и локальные адаптации записаны в
`.agents/skills/SOURCES.md`; обновление выполняется отдельным проверяемым изменением.

Для Next.js сначала используются документы установленной версии в
`node/apps/web/node_modules/next/dist/docs/`. Старый `next-best-practices` отдельно
не устанавливается. Архитектурные правила проекта имеют приоритет над общими
советами стороннего skill.

Context7 предоставляет документацию библиотек через удалённый MCP. Работа без
ключа зависит от публичного лимита сервиса; при исчерпании лимита используй
официальные/локальные документы. Не записывай API-ключ в версионируемый конфиг.
Next DevTools MCP запускается из закреплённого локального пакета и подключается к
Next.js dev server (`moon run web:dev`); production build не предоставляет его
диагностику. Браузером управляет Playwright CLI, отдельный браузерный MCP не нужен.
Terraform MCP запускается только с группой `registry`: поиск документации
провайдеров/модулей. Инструменты изменения HCP Terraform и облачных ресурсов
в этом сервере не включены. Документацию специфичных ресурсов Cloud.ru всё равно
нужно проверять у Cloud.ru.
При проверке этой настройки Terraform MCP не нашёл `cloudru/cloud` в публичном
реестре; его нельзя использовать как источник схемы нашего Cloud.ru-провайдера.

## Коммиты

Агент регулярно фиксирует законченные проверенные шаги. Формат:
`type(scope): summary`, например `fix(api): handle processor timeout`.
Scope необязателен. Заголовок — до 100 символов; английское описание без точки.
Конфигурация использует `@commitlint/config-conventional`.
`playground:node-check` проверяет общие Node-инструменты и поведение commit-msg
hook; `playground:agents-check` проверяет инструменты агентов. Обе проверки входят
в общий `playground:check` через наследование moon-задач.

```bash
moon run playground:commitlint -- --last --verbose
moon run playground:commitlint -- --from <base-sha> --to HEAD --verbose
```

Старые коммиты автоматически не переписываются. Hook проверяет новые коммиты
локально; он сам по себе не включает проверку истории на сервере CI.

## Проверка в браузере

```bash
moon run playground:browser-test
moon run playground:browser -- --help
```

Автоматический сценарий запускает три настоящих сервиса на свободных localhost
портах с временной SQLite/файловой директорией. Проверяет загрузку, преобразование,
опрос состояния, скачивание и ошибки входного файла. Данные рабочего приложения
не используются. Отчёты лежат в `.local/playwright/` и не коммитятся.

Для исследования живого локального приложения используй отдельную именованную
сессию Playwright CLI; закрывай только свою сессию. Скриншоты и browser traces
полезны как доказательства, но не заменяют проверку содержимого скачанного файла.

На нескольких реальных задачах оценивай время выполнения, повторные исправления
и найденные дефекты. Меняй состав ролей/skills по этим наблюдениям.
